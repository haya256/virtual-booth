# Virtual Booth の仕組み（アーキテクチャ）

## 全体構成

Virtual Booth は Next.js（App Router）で作られた1ページのWebアプリです。
ブースの見た目はすべて HTML と CSS で描かれており、画像素材やゲームエンジンは使っていません。

主なファイルは次のとおりです。

- `src/app/page.tsx`: トップページ。`content/guide.md` を読み、ブース名やスライドを画面に渡します。
- `src/app/api/chat/route.ts`: AIチャットのAPI。資料を検索し、AIの返答をストリーミングで返します。
- `src/components/Booth.tsx`: 壁・机・看板など、ブース全体のレイアウト。
- `src/components/Display.tsx`: スライドを映すディスプレイ。
- `src/components/ChatPanel.tsx`: RPG風の会話ウィンドウ。
- `src/components/Attendant.tsx`: AI担当者のキャラクター。
- `src/lib/guide.ts`: `guide.md` の解析。
- `src/lib/knowledge.ts`: 資料検索（ナレッジ検索）。
- `src/lib/slides.ts`: スライド定義の解析。

## 質問してから回答が表示されるまでの流れ

1. 来場者が会話ウィンドウに質問を入力します。
2. ブラウザが `/api/chat` に、これまでの会話履歴（直近10件まで）と一緒に質問を送ります。
3. サーバーが資料検索を行い、質問に関連する資料の抜粋を選びます。
4. `guide.md` の本文・スライド一覧・資料の抜粋をまとめてシステムプロンプトにし、AIに渡します。
5. AIの返答は SSE（Server-Sent Events）でブラウザへ少しずつ届きます。
6. 会話ウィンドウは届いた分から文字送りで表示し、`[SLIDE:N]` マーカーに合わせてディスプレイを切り替えます。

## 資料検索（ナレッジ検索）の仕組み

AIに毎回すべての資料を渡すのではなく、質問に関係する部分だけを選んで渡します。
このため、資料をたくさん置いてもAIの回答が遅くなったり、精度が落ちたりしにくくなっています。

検索の手順は次のとおりです。

1. `content/knowledge/` 内のファイル、`guide.md` の「参照ファイル」、「外部ソース」のURLを読み込みます。
2. それぞれを見出しごとに、約600文字の小さなかたまり（チャンク）に分けます。
3. 質問文とチャンクを単語に分け、BM25 というキーワード検索の方式で関連度を採点します。日本語は2文字ずつの組（バイグラム）に分けて比較します。
4. 点数の高いチャンクを、合計およそ3000文字まで選びます。
5. 選んだチャンクを出典名つきでAIに渡します。回答の下には「参照」として出典名が表示されます。

Embedding（ベクトル検索）やAIのツール呼び出し機能は使っていません。
そのため、Ollama の小さなローカルモデルを含め、どの OpenAI 互換 API でも同じように動きます。ベクトルデータベースなどの追加サービスも不要です。

追い質問（「それはどうやるの？」など）にも対応できるよう、直前の質問も少し弱い重みで検索に使います。

## 外部ソース（最新情報）の仕組み

`guide.md` の「外部ソース」に書いたURLを、サーバーが定期的に取得して資料検索の対象に加えます。

- 取得した内容は1時間キャッシュされます。取得に失敗した場合は5分後に再試行し、その間は前回の内容を使います。
- 1回の取得は5秒でタイムアウトします。失敗しても通常の回答は続けられます。
- HTML、Atom / RSS フィード、JSON、プレーンテキストに対応しています。
- 取得するのはブースの作者が `guide.md` に書いたURLだけです。来場者の入力やAIの出力からURLを取得することはありません。

## スライド連動の仕組み

AIは回答の中に `[SLIDE:3]` のようなマーカーを書きます。
会話ウィンドウはマーカーで回答を区切り、来場者が読み進めた位置に合わせてディスプレイのスライドを切り替えます。
マーカー自体は画面には表示されません。

スライドの一覧と「どんな話題のときに使うか」は、`guide.md` のスライド定義（`note:` 項目）から自動的にAIへ伝えられます。スライドの枚数に上限はありません。

## 会話ウィンドウの表示

- 回答は1ページ最大120文字で、句点（。！？）の位置で区切られます。
- 文字は1文字ずつ表示されます（文字送り）。Space・Enter・クリックで、表示中のページを一気に表示し、もう一度押すと次のページへ進みます。
- AIの返答は届いた分から順に表示されるので、長い回答でも待ち時間が短くなります。
- Esc キーで会話ウィンドウを閉じます。

## 画面サイズへの対応

ブースは 768×432 ピクセル（16:9）を基準に設計されており、`BoothScaler` というコンポーネントが、ブラウザの画面サイズに合わせて全体を拡大・縮小します。
スマートフォンやタブレットでも、レイアウトが崩れずに同じ見た目で表示されます。
