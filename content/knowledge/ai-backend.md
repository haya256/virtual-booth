# AIバックエンドの設定とデプロイ

## 環境変数

AIの接続先は3つの環境変数で指定します。ローカルでは `.env.local` に、Vercel ではダッシュボードの Settings → Environment Variables に設定します。

- `AI_BASE_URL`: AIのAPIエンドポイント。未設定の場合は `http://localhost:11434/v1`（Ollama）になります。
- `AI_API_KEY`: APIキー。Ollama などキーが不要な場合は適当な文字列で構いません。
- `AI_MODEL`: 使用するモデル名。未設定の場合は `llama3` になります。

`.env.example` をコピーして `.env.local` を作ると簡単です。

## 対応しているAIサービス

OpenAI 互換の Chat Completions API（ストリーミング対応）を持つサービスであれば利用できます。

- Ollama（ローカル実行）: `AI_BASE_URL=http://localhost:11434/v1`、モデルは `llama3.2` など
- LM Studio（ローカル実行）: `AI_BASE_URL=http://localhost:1234/v1`
- OpenAI: `AI_BASE_URL=https://api.openai.com/v1`、モデルは `gpt-4o` など
- さくらのAI Engine: `AI_BASE_URL=https://api.ai.sakura.ad.jp/v1`

必要なのは通常のチャット機能だけです。資料検索はアプリ側で行うため、Embedding API やツール呼び出し（Function Calling）に対応していないモデルでも、すべての機能が使えます。

## モデル選びの目安

- 資料を踏まえて正確に答えさせたい場合は、ある程度大きなモデルのほうが安定します。
- 小さなローカルモデルでは、`[SLIDE:N]` マーカーを書き忘れたり、回答が長くなったりすることがあります。その場合は `guide.md` の指示を短く具体的にすると改善します。
- 応答速度を重視する場合は、ストリーミングの速いサービスを選ぶと文字送りが途切れにくくなります。

## Vercel へのデプロイ

1. GitHub にリポジトリを用意します（このリポジトリをフォークしても構いません）。
2. Vercel でそのリポジトリをインポートします。
3. 環境変数 `AI_BASE_URL`・`AI_API_KEY`・`AI_MODEL` を設定します。
4. デプロイします。以降は `git push` するたびに自動でデプロイされます。

Vercel 上では、ローカルの Ollama のように自分のパソコンで動いているAIには接続できません。インターネットから到達できるAPIを指定してください。

`content/` ディレクトリのファイルは、`next.config.ts` の `outputFileTracingIncludes` によってサーバー側のバンドルに含まれます。`content/knowledge/` に資料を追加したら、コミットして push するだけで反映されます。

## Vercel 以外へのデプロイ

Node.js が動く環境であればどこでも動作します。

```bash
npm install
npm run build
npm run start
```

`npm run start` は既定で3000番ポートで待ち受けます。Docker やさくらのクラウド、自前のサーバーでも同じ手順です。

## 利用上の制限

- 質問は1回あたり40文字までです。超えるとエラーメッセージが表示されます。
- AIに送る会話履歴は直近10件までです。それより前のやり取りはAIには渡されません。
- 会話の内容はサーバーに保存されません。ページを再読み込みすると会話はリセットされます。
- 来場者ごとの利用回数制限（レート制限）は組み込まれていません。公開時に必要な場合は、AIサービス側の利用上限や、ホスティング側のファイアウォール機能で制限してください。

## うまく動かないとき

- 「エラーが発生しました」と表示される: `AI_BASE_URL`・`AI_API_KEY`・`AI_MODEL` が正しいか、AIサービスが起動しているかを確認してください。サーバーのログに `[chat/route] Error:` として原因が出力されます。
- スライドが切り替わらない: モデルが `[SLIDE:N]` マーカーを出力していない可能性があります。スライド定義の `note:` に、どんな質問のときに使うかを具体的に書いてください。
- 資料の内容を答えてくれない: 回答の下に「参照」が表示されているか確認してください。表示されない場合は、質問の言葉と資料の言葉が一致していません。資料の見出しに、来場者が使いそうな言葉を入れると見つかりやすくなります。
- 外部ソースの内容が反映されない: サーバーのログに `[knowledge] 外部ソースの取得に失敗` と出ていないか確認してください。反映には最大1時間かかります。
