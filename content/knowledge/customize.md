# カスタマイズ詳細ガイド

## content ディレクトリの構成

ブースの内容はすべて `content/` ディレクトリで管理します。コードを書き換える必要はありません。

```
content/
├── guide.md         ← AIへの指示・ブース設定・スライド
├── knowledge/       ← AIが検索して参照する詳細資料（何ファイルでも可）
├── images/          ← スライドに表示する画像
├── skin.css         ← カラーテーマ・アニメーション
├── pamphlet.html    ← パンフレット
└── attendant.svg    ← AI担当者のキャラクター
```

## guide.md の書き方

`guide.md` は「アプリが読み取るセクション」と「AIへの指示」の2種類でできています。

アプリが読み取るセクション（AIには直接渡されません）:

- `## ブース設定`: タイトル・サブタイトル・担当者名・パンフレットのファイル名
- `## 参照ファイル`: 資料検索の対象に加えるファイル
- `## 外部ソース`: 資料検索の対象に加えるURL
- `## おすすめの質問`: 会話ウィンドウに表示する質問ボタン
- `## ディスプレイスライド`: スライドの定義

それ以外のセクション（役割、製品紹介、よくある質問、トーンなど）は、そのままAIへの指示として毎回渡されます。
必ず守らせたいルールや、どんな質問でも前提になる基本情報は `guide.md` に書き、細かい情報や量の多い資料は `knowledge/` に置くのがおすすめです。

## 詳細資料（knowledge）の追加方法

`content/knowledge/` に Markdown（`.md`）、テキスト（`.txt`）、HTML（`.html`）のファイルを置くだけで、AIが質問に応じて検索するようになります。設定は不要で、サブフォルダに分けても構いません。

うまく検索されるためのコツ:

- 見出し（`#`・`##`・`###`）で内容を細かく区切る。見出しごとに検索されます。
- 見出しには、来場者が質問で使いそうな言葉を入れる。
- 1つの見出しの下には、1つの話題だけを書く。
- 料金表や仕様の一覧は、表よりも「項目: 値」の箇条書きのほうが正確に読み取られます。

PDF や Word の資料は、テキストか Markdown に変換してから置いてください。

## 外部ソースの追加方法

最新のお知らせや更新履歴など、頻繁に変わる情報は `guide.md` の「外部ソース」にURLを書きます。

```markdown
## 外部ソース
- 最近の更新履歴: https://github.com/ユーザー名/リポジトリ名/commits/main.atom
- お知らせ: https://example.com/news.xml
```

「表示名: URL」の形で書くと、表示名が出典名として使われ、検索の手がかりにもなります。
HTML ページ、Atom / RSS フィード、JSON を返す API、テキストファイルに対応しています。内容は1時間ごとに更新されます。

## スライドの書き方

`guide.md` の `## ディスプレイスライド` の下に、`### SLIDE:番号` で1枚ずつ定義します。枚数に上限はありません。

使える項目:

- `label`: 上部の小さな見出し
- `title`: 大きなタイトル文字（`|` で改行）
- `body`: 本文。複数行にする場合は `body: |` と書き、次の行から2文字インデントします。
- `items`: 絵文字つきの箇条書き
- `steps`: 番号つきの手順
- `code`: コマンドやコードの1行表示
- `image`: `content/images/` に置いた画像のファイル名（png・jpg・gif・webp・svg）
- `note`: AI向けのメモ。そのスライドの説明ポイントや、どんな質問のときに使うかを書きます。画面には表示されません。

例:

```markdown
### SLIDE:6
label: PRICING
items:
  - 🆓 フリー: 0円
  - 💼 プロ: 月額980円
note: 料金・プラン・無料かどうかを聞かれた時に使う。
```

`note` を書いておくと、AIがその話題のときに自動でスライドを切り替えて説明します。
ディスプレイは小さいので、1枚に載せる文字は少なめにし、詳しい説明はAIの回答に任せるのがコツです。

## おすすめの質問ボタン

`guide.md` に次のように書くと、会話ウィンドウを開いたときに質問ボタンとして表示されます。

```markdown
## おすすめの質問
- このブースを紹介して
- 料金を教えて
```

来場者は何を聞けばよいか迷いがちなので、3〜4個用意しておくと会話が始まりやすくなります。1つの質問は40文字以内にしてください。

## スキン（skin.css）で変えられるもの

`content/skin.css` の CSS 変数を書き換えると、ブース全体の配色が変わります。

- `--vb-bg`: ページの背景色
- `--vb-wall-start` / `--vb-wall-mid` / `--vb-wall-end`: 壁のグラデーション
- `--vb-border`: ブースの枠線
- `--vb-accent`: 看板のネオン色、机のライン
- `--vb-sign-bg`: 看板の背景色
- `--vb-display-border`: ディスプレイの枠・スライド見出しの色
- `--vb-screen-bg` / `--vb-screen-text`: スライド画面の背景色と文字色
- `--vb-desk-top` / `--vb-desk-bottom` / `--vb-desk-edge`: 机の上面と縁
- `--vb-desk-front-top` / `--vb-desk-front-bottom`: 机の前面
- `--vb-text-primary` / `--vb-text-secondary` / `--vb-text-muted`: 文字色
- `--vb-chat-bg` / `--vb-chat-border`: 会話ウィンドウ
- `--vb-spot`: スポットライトの光の色
- `--vb-font-dialog`: 看板と会話ウィンドウのフォント

変更後は開発サーバーを再起動すると反映されます。

## キャラクターの差し替えとアニメーション

`content/attendant.svg` を置き換えると、AI担当者の見た目が変わります。

担当者には、会話の状況に応じて次の3つの状態が付きます。

- `idle`: 待機中。ゆっくり上下に揺れます。
- `thinking`: AIが考え中。少し首をかしげます。
- `talking`: 回答を表示中。口が動きます（口パク）。

SVG の中の口のパーツに `id="attendant-mouth"` を付けておくと、会話中に自動で口パクします。
`skin.css` から `.vb-attendant[data-state="talking"]` のようなセレクタを使うと、状態ごとに独自のアニメーションを付けられます。

OSの「視差効果を減らす」設定が有効な来場者には、アニメーションは自動的に抑えられます。

## パンフレットの編集

`content/pamphlet.html` を編集すると、机の上のサムネイルにも自動で反映されます。
`/pamphlet` にアクセスすると全画面で表示され、ブラウザの印刷機能で PDF として保存できます。
別のファイル名を使いたい場合は、`guide.md` の「ブース設定」の「パンフレット」を書き換えます。
